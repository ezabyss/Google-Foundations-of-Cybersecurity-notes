# 🧠 Security Mindset & Data Classification  

---

# 🔐 What Is a Security Mindset?

A **security mindset** is:

> The ability to continuously evaluate risk and actively look for potential or actual system, application, or data breaches.

It means thinking:

- What are we protecting?
- Who are we protecting it from?
- What could go wrong?
- What happens if this asset is compromised?

Security is not reactive.  
Security is proactive.

---

# 🎯 Core Principle

Every click.
Every login.
Every configuration change.
Every exposed port.

Has potential security implications.

That awareness is the foundation of a security mindset.

---

# 🛡 What Are You Defending?

Security professionals protect:

- Systems

But protection starts with identifying assets and understanding risk.

---

# ⚠ Understanding Threats, Risks, and Vulnerabilities

| Term | Meaning |
|------|----------|
| Threat | A potential cause of harm |
| Vulnerability | A weakness that can be exploited |
| Risk | The potential impact if a threat exploits a vulnerability |

Example:

Phishing email  
→ Human vulnerability  
→ Credential theft  
→ Financial loss  

Security mindset means spotting this chain before damage occurs.

# 📊 Data Classification: Why It Matters

Not all data needs the same level of protection.

Classifying data helps:

✔ Prioritize defenses  
✔ Allocate resources  
✔ Prevent over- or under-securing assets  
✔ Respond properly during incidents  

---

# 📁 The 4 Main Data Classifications

---

## 1️⃣ Public Data (Low-Level Asset)

Publicly accessible information.

Examples:
- Press releases
- Job postings
- Marketing materials
- Website address

Risk if leaked:
Low (but still should be protected from tampering).

Security focus:
Integrity and availability.

---

## 2️⃣ Private Data

Information not meant for public access.

Examples:
- Internal email addresses
- Employee IDs
- Research data

Risk if leaked:
Moderate to high.

Security focus:
Access control and monitoring.

---

## 3️⃣ Sensitive Data (High-Level Asset)

Requires strong protection.

Unauthorized access can cause:

- Financial damage
- Legal consequences
- Reputational harm

Examples:
- PII (Personally Identifiable Information)
- SPII (Sensitive PII)
- PHI (Protected Health Information)
- Banking information
- Passwords
- Passport numbers
- Medical records

Security focus:
Encryption, strict access control, monitoring, logging.

---

## 4️⃣ Confidential Data (High-Level Asset)

Critical to business operations.

Often restricted to limited personnel.

Examples:
- Trade secrets
- Financial records
- Proprietary algorithms
- Government contracts
- NDA-protected information

Security focus:
Need-to-know access, monitoring, legal protections.

---

# 🏷 Asset Classification

Asset classification = labeling assets by importance and sensitivity.

---

## Low-Level Assets

Impact if compromised:
Minimal operational damage.

---

## High-Level Assets

- Intellectual property
- Financial systems
- Customer databases
- Authentication systems
- Trade secrets

Impact if compromised:
Severe financial, legal, reputational damage.

# 🧠 Security Mindset in Action (Real Scenarios)

---

## 🏥 Healthcare Example

Asset: Patient records (PHI)

Threat: Brute-force login attempt  
Vulnerability: Weak authentication  
Risk: Data breach, regulatory fines  

Security mindset response:
- Monitor login attempts
- Lock account after threshold
- Log unusual activity
- Alert security team

---

## ⚖ Law Firm Example

Asset: Client data  

Flag conditions:
- Login at 3:00 AM
- Login from unknown country
- Same user logged in from two IPs simultaneously

Security mindset:
Assume anomaly = potential compromise.

---

## 💼 Enterprise Example

Asset: Customer-facing application  

Rule:
If failed_login_attempts >= 3 within 30 minutes  
→ Flag account  

Security mindset:
Automation + monitoring = prevention.
